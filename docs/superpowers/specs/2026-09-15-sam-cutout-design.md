# 누끼(SAM) 기능 설계

작성일: 2026-09-15 · 상태: 구현됨. 같은 날 SAM 3 로 교체했다 — 맨 아래 "변경: SAM 3 교체" 가 위 내용보다 우선한다.

## 목표

런처의 `누끼` 타일을 누르면 화면이 어두워지고, 마우스를 올린 대상만 밝게 드러난다. 클릭하면 그 대상을
투명 배경으로 따 낸 이미지가 작은 뷰어에 뜨고, 뷰어에서 복사하거나 저장한다. 모드 중 우클릭은 취소다.

## 결정된 사항

| 항목 | 결정 |
|---|---|
| 사용 PC | 이 PC만 (RTX 4070 Laptop, 인터넷 가능). 다른 PC 배포는 고려하지 않는다 |
| 분할 방식 | SAM 2.1 **hiera-small fp16** ONNX + ONNX Runtime DirectML 1.23.0 (GPU) |
| 화면 | **라이브.** 멈춘 캡처가 아니라 계속 바뀌는 실제 화면을 어둡게 보여준다 |
| 분석 영역 | 커서 주변 1024×1024 물리 픽셀 (원본 해상도). 이보다 큰 대상은 가장자리에서 잘린다 |
| 클릭 후 | 모드 종료, 뷰어만 남는다 |
| 뷰어 | 딸 때마다 새로 띄운다 (여러 개 공존) |
| 타일 위치 | V 메뉴 링 (타일 6개) |
| 강조 | 대상 영역을 원래 밝기로 + 경계에 2px 흰 테두리 |
| 모델 메모리 | 모드 시작 때 올리고 모드가 끝나면(클릭·취소 모두) 내린다 |
| 모델 파일 | 처음 쓸 때 `%AppData%\VisionSupport\Sam\sam2.1-hiera-small-fp16\` 로 내려받는다 (약 88MB) |
| GPU 실패 시 | 메시지로 알리고 시작하지 않는다. CPU 대체는 하지 않는다 (CPU 인코딩 약 690ms 로 라이브가 안 된다) |

## 구조

```
src/VisionSupport.Sam            (새 클래스 라이브러리 · net9.0-windows · WPF)
 ├ PixelRect / SamGeometry  크롭 위치, 화면 ↔ 모델 좌표 (순수)
 ├ EncodePolicy             인코딩을 다시 할지 판단 (순수)
 ├ SamPreprocess            BGRA 크롭 → 1024 정규화 텐서 (순수)
 ├ SamPostprocess           최적 마스크 선택, 256 로짓 → 크롭 크기 이진 마스크 (순수)
 ├ MaskOverlay              이진 마스크 → 막에 얹을 BGRA (밖 어둡게·안 투명·경계 흰색) (순수)
 ├ Cutout                   크롭 + 마스크 → 투명 배경 이미지 (순수)
 ├ ModelStore               모델 파일 확인·다운로드
 ├ DirectMlLoader / GpuAdapters   DirectML DLL 선로딩, 고성능 GPU 선택
 ├ SamModel                 인코더·디코더 세션
 ├ Monitors / ScreenFrame   모니터 목록, 모니터별 실시간 캡처 버퍼 (GDI)
 ├ CutoutOverlay            모니터별 전체화면 막 창
 ├ DownloadWindow           첫 다운로드 진행 창
 ├ CutoutViewer             누끼 뷰어 창 (+ 복사·저장)
 └ CutoutSession            모드 한 번의 수명
src/VisionSupport (셸)
 └ 링에 `누끼` 타일 (아이콘 ContentCut) → CutoutSession.RunAsync()
```

기존 `IFeatureModule` 은 쓰지 않는다. 창을 여는 기능이 아니고, 모드가 끝나면 뷰어 말고는 아무것도 남지
않는다. 셸 → Sam 방향으로만 참조한다.

## 동작 흐름

1. **타일 클릭** — 메뉴가 즉시 접힌다. 이미 모드 중이면 무시한다.
2. **모델 파일** — 없으면 작은 진행 창을 띄우고 내려받는다. 실패하면 메시지 후 끝.
3. **막 표시** — 모니터마다 전체화면 `CutoutOverlay` 를 띄운다.
   - 막은 **불투명 창**이고 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 로 캡처에서 빠진다.
     그래서 막을 덮은 채로 그 아래 실제 화면을 캡처할 수 있다. 막은 그 캡처를 받아 계속 다시 그리고,
     위에 55% 검정을 얹어 어둡게 보인다.
     (반투명 창에는 이 API 가 실패한다 — 스파이크에서 확인. 그래서 반투명 막이 아니라 다시 그리는 방식이다.)
   - 캡처 주기: 커서가 있는 모니터는 쉬지 않고, 나머지 모니터는 200ms 마다.
   - 막은 Topmost 이고 마우스를 받는다. 모드 중 아래 프로그램은 조작되지 않는다.
   - 모든 좌표는 물리 픽셀로 다룬다(앱은 PerMonitorV2). 창 배치도 물리 픽셀로 `SetWindowPos`.
   - 모델을 올리는 동안 커서 옆에 "준비 중"을 띄운다.
4. **루프** (백그라운드 한 줄, 최신 커서만 처리)
   - **인코딩**: 아래 중 하나일 때만 새로 한다.
     아직 한 번도 안 했을 때 / 커서가 마지막 인코딩 때 위치에서 가로나 세로로 128px 넘게 움직였을 때 /
     커서가 마지막 크롭 밖으로 나갔을 때 / 마지막 인코딩 후 400ms 가 지났을 때.
     크롭은 커서 중심 1024×1024 를 커서가 있는 모니터 안으로 밀어 넣은 것. 픽셀은 그 모니터의 최신
     캡처 버퍼에서 잘라 온다(따로 캡처하지 않는다).
   - **디코딩**: 새 인코딩이 끝났을 때와 커서가 움직였을 때.
   - **표시**: `object_score_logits < 0` 이면 대상 없음 — 크롭 전체를 어둡게. 아니면 `iou_scores` 가 가장
     높은 마스크를 크롭 크기로 확대해 안은 투명, 밖은 55% 검정, 경계 2px 흰색으로 그린 이미지를 크롭
     위치에 얹는다. 크롭 바깥은 55% 검정 사각형.
5. **좌클릭** — 현재 표시 중인 마스크와 그 마스크를 만든 인코딩의 크롭 픽셀로 누끼를 만든다. 대상이
   없으면 무시한다. 막을 닫고 모델을 내린 뒤, 커서 근처에 뷰어를 띄운다.
6. **취소** — 막 위 우클릭 또는 Esc. 막을 닫고 모델을 내린다.

## 누끼 이미지와 뷰어

- 마스크: 256×256 로짓을 크롭 크기로 쌍선형 확대 후 0 에서 잘라 이진 마스크로 쓴다.
- 결과: 마스크 외곽 사각형으로 자른 BGRA. 마스크 밖은 알파 0, 색도 0.
- 뷰어: 테두리 없는 작은 창, 체커보드 배경, 긴 변 400px 안으로 축소 표시(작으면 원본 크기, 원본은
  그대로 보관), 드래그로 이동, 우측 상단 × 로 닫기. Topmost.
- 뷰어 우클릭 메뉴
  - **복사**: 클립보드에 `PNG` 형식(투명 유지)과, 흰 배경에 합성한 일반 비트맵을 함께 넣는다.
  - **저장…**: PNG 저장 대화상자. 기본 이름 `누끼_yyyyMMdd_HHmmss.png`.

## 모델과 런타임

- 파일: `https://huggingface.co/onnx-community/sam2.1-hiera-small-ONNX/resolve/main/onnx/` 의
  `vision_encoder_fp16.onnx(+_data)`, `prompt_encoder_mask_decoder_fp16.onnx(+_data)`. 완결성은 파일 크기로 판단.
- 텐서 (스파이크에서 확인, fp16 모델도 입출력은 float32)
  - 인코더 입력 `pixel_values [1,3,1024,1024]` — 1024 고정(512 는 거부됨). ImageNet 평균/표준편차, rescale 1/255.
  - 인코더 출력 `image_embeddings.0 [1,32,256,256]`, `.1 [1,64,128,128]`, `.2 [1,256,64,64]`
  - 디코더 입력 `input_points [1,1,1,2]`(1024 좌표), `input_labels [1,1,1]` int64 = 1,
    `input_boxes [1,0,4]`(빈 텐서), 인코더 출력 3개
  - 디코더 출력 `iou_scores [1,1,3]`, `pred_masks [1,1,3,256,256]`, `object_score_logits [1,1,1]`
- **DirectML DLL 선로딩 (필수)**: `onnxruntime.dll` 의 의존성 `DirectML.dll` 은 실행 호스트 폴더 → System32
  순서로 찾아진다. `dotnet.exe`/`testhost.exe` 로 돌면 System32 의 DirectML 1.0 이 먼저 잡혀
  `DMLCreateDevice1(FL 5.0)` 이 `DXGI_ERROR_UNSUPPORTED` 로 실패한다. 세션을 만들기 전에 앱 폴더 또는
  `NATIVE_DLL_SEARCH_DIRECTORIES` 의 `DirectML.dll`(1.15.4) 을 `NativeLibrary.Load` 로 먼저 올린다.
- GPU 선택: DXGI 어댑터 중 소프트웨어가 아닌 것 가운데 전용 메모리가 가장 큰 것. (이 PC 에서는 0번 RTX 4070)
- 배포: 네이티브 DLL 이 단일 exe 에 포함된다(단일 exe 에서 GPU 동작 확인).

## 테스트

- 단위: 크롭 위치(모니터 가장자리·작은 모니터), 화면 → 모델 좌표, 인코딩 재실행 조건, 전처리 정규화 값,
  최적 마스크 선택, 마스크 확대·임계값, 막 오버레이 픽셀, 누끼 외곽·알파, 모델 파일 완결성·다운로드
  (가짜 HTTP), GPU 어댑터 선택, 뷰어 표시 크기·기본 파일 이름·PNG 왕복·클립보드 데이터.
- 모델: 모델 파일이 있을 때만 실제 GPU 로 합성 사각형을 따서 마스크가 사각형을 덮는지 확인.
- 화면(막, 뷰어, 흐름)은 실행해서 확인한다.

## 변경: SAM 3 교체 (2026-09-15)

사용자 요청으로 SAM 3 로 바꾸고, 인코딩과 디코딩을 스레드로 나눴다. 메모리는 측정으로 확인된 문제만 조치했다.

| 항목 | SAM 2.1 small fp16 (이전) | SAM 3 tracker fp16 (현재) |
|---|---|---|
| 모델 | 약 88MB | 약 900MB, `onnx-community/sam3-tracker-ONNX` |
| 입력 / 정규화 | 1024 / ImageNet | **1008 / 평균·표준편차 0.5** |
| 임베딩 | [1,32,256,256] [1,64,128,128] [1,256,64,64] | [1,32,288,288] [1,64,144,144] [1,256,72,72] |
| 마스크 | 256×256 | **288×288** |
| 로드 | 0.65s | 1.7~2.0s |
| 인코딩 | 52~62ms | **약 395ms** (첫 회 0.8~1.2s) |
| 디코딩 | 8ms | 9~10ms |
| 모드 중 메모리 | RAM 약 1.35GB · GPU 약 0.9GB | RAM 약 3.2GB · GPU 약 2.6GB |

**구조**

- 인코딩 스레드: `EncodePolicy` 가 낡았다고 할 때만 커서 주변을 인코딩해, 아무도 읽지 않는 슬롯에 쓰고
  공개한다. 슬롯은 3개(`HandoffPool`: 현재 · 읽는 중 · 쓰는 중)이고 새로 만들지 않는다.
- 디코딩 스레드: 가장 최근에 공개된 인코딩으로 커서를 계속 따라간다. 인코딩을 기다리지 않는다. 커서가
  인코딩된 크롭 밖이면 새 인코딩이 올 때까지 강조하지 않는다.
- 재인코딩 시간 기준 400ms → **1초** (인코딩이 0.4초라 400ms 면 GPU 가 쉬지 않는다).
- "준비 중" 은 첫 마스크가 그려질 때 사라진다.

**메모리**

- 문제 (측정): 모드를 쓸 때마다 약 125MB 증가 (4회 745 → 1023MB). 강제 수집하면 622MB 로 돌아가고 이후 늘지
  않음 → 디코딩마다 새로 만든 대형 버퍼가 모드 뒤에도 수집되지 않은 것.
- 조치: 텐서·임베딩·마스크·오버레이·모델 입출력 버퍼를 모드 시작 때 한 번 만들어 재사용(ONNX Runtime 에는
  `OrtValue` 로 한 번 바인딩), 모드 종료 시 전부 해제하고 즉시 수집, 취소 토큰 dispose.
- 결과 (SAM 3, 실제 모드 4회): 658 → 657 → 679 → 681MB, 사용 직후 관리 메모리 매번 1MB.
- 조치하지 않은 것: 첫 사용 뒤 ONNX Runtime·DirectML·드라이버가 잡고 있는 수백 MB, 사용마다 조금씩 늘어나는
  핸들(모델 로드·해제만 반복해도 4개씩 늘어 ONNX Runtime 내부로 확인). 사용자 결정으로 추가 추적은 하지 않았다.

## 변경: 마스크 선택과 정리 (2026-09-15)

사용 피드백: 상용 누끼보다 노이즈가 심하고, 사람 전체가 아니라 상의·머리·바지처럼 부분이 잡힌다.

- **선택 (A)**: 모델 점수 최고 대신 **면적 순**. 기본은 가장 큰 마스크, 휠 아래로 다음 작은 마스크, 위로 다시
  큰 쪽. 점수 0.5 미만 마스크는 제외(모두 미만이면 전부 후보). 휠 단계는 모드가 끝날 때까지 유지.
- **정리 (B)**: 확대한 마스크에서 커서 아래 4-연결 덩어리만 남긴다(커서가 마스크 밖이면 가장 큰 덩어리).
  크롭 테두리에 닿지 않는 배경 구멍 중 남긴 덩어리 면적의 1% 미만은 메운다. 작업 버퍼는 모드 시작 때 한 번 만든다.
- 스파이크 (사람 모양 합성: 머리 원 + 몸통 사각형, 몸통을 찍음): 마스크 3개 = 점수 0.02·면적 0.5%(버림용),
  0.98·13.3% 몸통, 0.96·13.3% 몸통. 가장 큰 마스크가 배경을 잡지는 않았지만, 어느 마스크도 머리까지 합치지
  않았다 — 색이 뚜렷이 다른 부분은 점 하나로는 한 덩어리가 되지 않을 수 있다. 실제 사진에서의 동작은 사용해 보고
  판단한다.

## 변경: 휠 단계 표시 (2026-09-15)

사용자 요청: 휠로 전체/부분을 바꿀 때 지금 몇 단계인지 알 수 있게.

- `ChooseMask` 가 고른 인덱스만이 아니라 `MaskChoice(Index, Level, Total)` 를 돌려주도록 바꿨다 — `Level` 은
  실제로 보여준 단계(요청한 단계가 범위를 넘으면 마지막 단계로 clamp된 값), `Total` 은 그때 신뢰 임계값(0.5)을
  넘겨 후보에 남은 마스크 개수(대상에 따라 1~3).
- `LevelLabel.Format(level, total)` 이 "1/3" 같은 1-기반 문자열을 만든다.
- 휠(`ChangeLevel`)은 고정된 3이 아니라 마지막으로 받은 `Total`(`_availableLevels`, decoder 스레드가 매
  디코딩마다 갱신) 범위 안에서만 움직인다 — 그렇지 않으면 후보가 2개뿐일 때 계속 내려도 내부 값만 커져서,
  다시 올릴 때 몇 번을 올려야 반응하는지 알 수 없는 문제가 생긴다.
- 라벨은 커서 오른쪽 위, 지수처럼 작게 떠 있는 `CutoutOverlay._levelLabel` 로 그린다. 강조 대상이 없으면
  숨긴다(`ShowLevel(null, …)`).
- 실제 GPU 로 5초 스모크 실행: 커서에 겹친 합성 원판을 보여주고, 스크린샷으로 라벨이 커서 옆에 "1/1" 로
  제대로 뜨는 것과 강조·경계가 여전히 정상인 것을 확인했다.

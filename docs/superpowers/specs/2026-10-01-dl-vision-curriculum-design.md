## 1. 목적과 독자

**독자.** 비전 검사·측정 업무는 하고 있으나 딥러닝은 처음인 현업 엔지니어. 파이썬은 조금 다룰 줄 안다. 사내 Windows PC + NVIDIA GPU 환경.

**목적.** 이 자료를 끝까지 본 사람이 혼자서 다음을 할 수 있어야 한다.

1. 눈앞의 과제가 딥러닝을 쓸 일인지, 고전 비전으로 끝날 일인지 가린다
2. 이미 만들어진 도구로 되는 일인지 확인하고, 되면 그것부터 쓴다
3. 안 되면 데이터를 모으고 라벨링해서 직접 학습시킨다
4. 만든 모델을 기존 C#/WPF 프로그램에 추론으로 붙인다
5. 붙인 뒤 성능이 떨어지는 것을 감지하고 대응한다

**명시적 비목표.** 논문을 읽고 모델을 설계하는 능력, 수식 유도, 최신 아키텍처의 내부 원리. 필요한 깊이는 "증상을 보고 설정을 고칠 수 있는 수준"까지다.

## 3. 작성 규칙

이전 PLC 프로토콜 자료에서 지적받은 9가지를 규칙으로 고정한다. **이 규칙은 협상 대상이 아니다.**

| # | 규칙 | 금지되는 것 |
|---|---|---|
| 1 | 개념은 **쓰임을 먼저**, 정의는 그다음 | "X는 ~이다"로 시작하는 쪽 |
| 2 | 처음 나오는 용어·값은 **그 자리에서** 설명 | 뒤에서 설명할 것을 미리 던지기 |
| 3 | 줄임말 금지 — 표 안에서도 풀어쓴다 | `IG`, `lr`, `bs`, `aug` 같은 축약 |
| 4 | 파트는 **"이게 없으면 뭐가 곤란한가"** 로 연다 | 정의·역사·분류부터 시작 |
| 5 | 앞 쪽이 남긴 질문에 이 쪽이 답하는 **사슬** | 독립된 항목 나열 |
| 6 | 각 쪽은 **"전체 중 여기"** 를 먼저 밝힌다 | 맥락 없이 확대도부터 |
| 7 | 고칠 때는 **같은 문제를 전부** 찾아 일괄 수정 | 지적받은 곳만 수정 |
| 8 | 기술은 **공식 문서·논문 기준**, 우리 코드는 부차 | 구현 중심 설명 |
| 9 | **한 쪽에 한 가지.** 넘치면 쪽을 쪼갠다 | 밀어 넣기 |

### 추가 규칙 — 이 자료 고유

| # | 규칙 | 이유 |
|---|---|---|
| 10 | 모든 수치·모델명·버전은 **출처 링크**를 단다 | 이 분야는 반년이면 바뀐다 |

| 17 | **절·장의 제목을 개념 이름으로 열지 않는다.** "보안 모델"이 아니라 "인증서를 안 맞추면 접속 자체가 안 된다" | 개념이 존재한다는 이유만으로 설명에 들어가면 왜 읽는지를 알 수 없다 |

## 3-A. 개념 도입 슬라이드의 필수 다섯 칸

개념·기능·설정을 처음 꺼내는 슬라이드는 **아래 다섯 칸을 모두 채울 수 있을 때만** 쓴다. 하나라도 못 채우면 그 내용은 자료에서 뺀다.

| 칸 | 묻는 것 | 못 채우면 생기는 일 |
|---|---|---|
| **① 왜 지금** | 앞 장에서 생긴 **어떤 문제**가 이걸 요구하나 | 앞 얘기 하다 갑자기 넘어간 것처럼 보인다 |
| **② 언제 쓰나** | 전체 흐름의 **어느 시점·구간**인가. 최초 1회인가, 접속마다인가, 패킷마다인가 | 읽어도 언제 꺼내 쓸지 모른다 |
| **③ 어디서 만나나** | **실물 위치** — 어느 화면의 어느 칸 · 어느 함수의 몇 번째 인자 · 패킷의 몇 바이트 · 어느 로그 메시지 | 개념으로만 남고 손이 안 간다 |
| **④ 누가 정하나** | 나 / 상대 장비 / 규격 고정 / 관리자 | 내가 할 일인지 아닌지 모른다 |
| **⑤ 틀리면** | 어떤 증상이 나오나 | 문제가 생겨도 여기를 못 떠올린다 |

### 함께 지킬 것

- **③은 "실물"이어야 한다.** "설정에서 지정한다"는 ③이 아니다. "UaExpert 접속 대화상자의 Security Mode 드롭다운"처럼 **독자가 눈으로 찾을 수 있는 위치**여야 한다.
- **설명에 쓰는 말은 그 시점에 이미 설명된 말이어야 한다.** "GetEndpoints를 부르면 보안 모드·보안 정책·사용자 토큰 조합을 준다"처럼 **모르는 말로 모르는 말을 설명하지 않는다.** 설명이 또 다른 미설명 용어를 낳으면 그 슬라이드는 실패다.
- **알 필요 없는 것은 "알 필요 없다"고 적는다.** 암호 알고리즘 이름(AES-128 등)처럼 내부를 몰라도 되는 것은 **"양쪽이 같은 것을 고르기만 하면 된다"**고 분명히 밝힌다. 설명 없이 던지는 것도, 불필요하게 파고드는 것도 둘 다 나쁘다.

## 4. 자료를 관통하는 축 — 다섯 갈래 결정

전 파트에서 반복해서 되돌아오는 기준이다. 독자가 "지금 몇 번 길인지" 항상 알 수 있어야 한다.

```
① 고전 비전(OpenCV)으로 되나?
      되면 그걸로 끝 — 빠르고 · 설명 가능하고 · 데이터 0

② 기성 모델이 이미 그 일을 하나?
      MediaPipe · PaddleOCR · Depth Anything 그대로 — 학습 0

③ 비슷한데 대상만 내 것인가?
      미세조정 — 데이터 수백 장

④ 아예 다른 문제인가?
      직접 학습 — 데이터 수천 장 + 라벨링 공수

⑤ 불량 종류를 다 알 수 없나?
      이상탐지 — 정상품만 모으면 됨
```

## 6. 파트별 내용

### 01 · 왜 딥러닝인가 (40쪽)

룰 기반으로 되는 것과 안 되는 것을 먼저 가른다. 안 되는 사례 5개(조명 변동, 자연 텍스처 불량, 형태 다양성, 미지 불량, 글자 판독)를 실제 이미지 비교로 보여준다.

**"언제 쓰지 말아야 하나"를 반드시 포함한다.** 임계값으로 끝날 일을 딥러닝으로 하는 것이 현장 최대 낭비다. 판단 기준: 조명과 대상이 고정되어 있고 · 불량 종류가 유한하고 · 규칙을 말로 쓸 수 있으면 고전 비전.

시장 숫자는 동기부여용으로만 쓴다(§7 표 참조).

### 02 · 개발환경 (45쪽)

GPU 드라이버 → CUDA → PyTorch의 **의존 관계 그림**부터. 버전이 왜 맞물려야 하는지 이해시킨 뒤 설치 순서를 따라가게 한다.

- 가상환경 = 프로젝트별 공구함 (왜 필요한지부터)
- 설치 단계마다 **검증 명령과 기대 출력**
- 실패 사전: 증상 → 원인 → 조치 표 (CUDA 불일치, DLL 누락, 드라이버 구버전, 메모리 부족 등 12가지)
- 폴더 구조 관례 (데이터·실험·모델 분리)

### 03 · 가져다 쓰기 — 도구 대전 (120쪽) — 이 자료의 1차 차별점

**방침: 추리지 않는다.** 목적마다 쓸 수 있는 것을 전부 늘어놓고, 비교표와 **고르는 기준**을 준다. 읽는 사람이 자기 상황으로 필터링한다.

| 오픈 웨이트 | Qwen3-VL · InternVL3 · LLaVA-OneVision · Florence-2 · PaliGemma2 · MiniCPM-V · Molmo |
| 상용 API | GPT 계열 · Gemini · Claude |

#### 고전 비전 — 잊지 말 것 (약 6쪽)
OpenCV의 임계값·형태학·에지·템플릿매칭·허프변환·블롭. **딥러닝보다 빠르고 설명 가능하고 데이터가 필요 없다.** 이걸로 끝날 일을 딥러닝으로 하는 것이 현장 최대 낭비다.

#### 라이선스 (약 14쪽) — 이 파트에서 가장 중요
- YOLOv5 · v8 · 11 · 26 = **AGPL-3.0.** 폐쇄소스 상용 제품 불가, 네트워크 서비스도 소스 공개 의무
- Apache 2.0 대안: RF-DETR · RT-DETR · YOLOX · PP-YOLOE · DAMO-YOLO
- 모델별 라이선스 일람표 (위 모든 도구에 대해)
- 판정 흐름: **사내 도구 / 납품 제품 / SaaS** 세 경우로 나눠 쓸 수 있는지 결정

#### 고르는 기준 (약 6쪽)
선택지가 많을수록 기준이 필요하다. 다음 축으로 비교표를 제공한다.

정확도 · 속도(CPU/GPU) · 라이선스 · 메모리 · 설치 난이도 · 커뮤니티 활성도 · 한국어 자료 유무 · ONNX 변환 가능 여부 · 상용 지원 유무

### 04 · 기초 개념 (50쪽)

03에서 도구를 써 본 뒤라, "방금 그게 왜 됐나"를 설명하는 위치가 된다.

모든 개념을 **증상과 짝지어** 가르친다.

| 개념 | 가르치는 방식 |
|---|---|
| 학습률 | "너무 크면 손실이 널뛴다 → 낮춘다" |
| 배치 크기 | "너무 크면 메모리 부족 에러 → 줄인다" |
| 에폭 | "학습 손실은 주는데 검증 손실이 오르면 과적합 → 멈춘다" |
| 과적합 | "학습 데이터는 100%인데 현장에서 틀린다" |
| 전이학습 | "남이 배운 걸 물려받아 내 것만 조금 가르친다" |
| 데이터 분할 | "시험 문제를 미리 보여주면 안 된다" |

CNN과 Transformer는 **고를 일이 생겼을 때의 기준만** 다룬다(속도·데이터량·해상도).

### 05 · 데이터와 라벨링 (85쪽)

- 과제 유형별로 필요한 라벨이 다르다 (분류/검출/분할/이상탐지)

- **라벨링 도구 전수 비교 (약 12쪽)** — CVAT · Label Studio · X-AnyLabeling · AnyLabeling · Roboflow · Supervisely · labelme · LabelImg · Makesense.ai · FiftyOne(데이터 탐색·오류 찾기) · Encord · V7
  - 축: 무료 여부 · 온프레미스 가능 · SAM 지원 버전 · 영상 지원 · 포맷 내보내기 · 협업·검수 기능 · 한국어
- **SAM 3 오토 레이블링 실전** — 텍스트 프롬프트로 사전 라벨 → 사람이 검수. CVAT의 라벨 기반 텍스트 프롬프트 기능 포함

## 8. 기술 사양

**형식.** 기존 `docs/plc-protocol-deep-dive-v2.html`과 같은 고정 1920×1080 스테이지, 단일 HTML, 인라인 CSS/JS. 폰트는 Google Fonts.

**재사용할 컴포넌트.** PLC 자료에서 검증된 것을 그대로 가져온다.

| 컴포넌트 | 용도 |
|---|---|
| `.where` | 위치 표시 — 이 쪽이 전체 어디인지 |
| `.useblk` | 쓰는 자리 — 누가 정하나 / 내 코드에선 / 틀리면 |
| `.tbl` · `.callout` · `.cards` · `.code` | 표·강조·카드·코드 |
| 목차 오버레이(`O`) · 번호 점프 · 진행 바 | 네비게이션 |

**추가할 컴포넌트.**

| 컴포넌트 | 용도 |
|---|---|
| `.pathbadge` | 다섯 갈래 중 몇 번 길인지 표시 |
| `.license` | 모델 라이선스 배지 (Apache 2.0 / AGPL / 상용) |
| `.codelink` | `code/` 폴더의 실행 가능한 예제로 연결 |
| `.crossfile` | 다른 파트 파일로 이동 |

**파일 간 이동.** `index.html`이 전체 목차를 들고 있고, 각 파트 파일의 목차 오버레이 맨 위에 다른 파트 링크를 둔다. 파트 내 이동은 기존 방식 그대로.

**테마.** PLC 자료와 구분되는 별도 색 체계를 쓴다 (두 자료를 나란히 열 때 혼동 방지).

## 12. 진행 순서
